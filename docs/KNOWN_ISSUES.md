# Known limitations and deferred features

- Native Windows/macOS capture runtime and physical WLED/HA light behavior need tests on real systems. Current verified desktop is Hyprland Wayland; GNOME/KDE/other wlroots environments are untested.
- Portal chooser is synchronous inside scap. Stop ends output but cannot immediately dismiss a pending chooser; cancel/select in the system dialog. Restart is refused while that worker is pending. Closing exits the process.
- Explicit macOS ScreenCaptureKit Idle notifications identify an unchanged image: the application keeps using that cached image while these notifications continue. Silence without an image or explicit Idle for two seconds stops streaming conservatively and requires Start. Linux/Windows backends do not currently expose equivalent idle health, so some unchanged desktops may still trigger this cutoff. A gap over five seconds also requires restart after interruption. These new macOS semantics have synthetic coverage and source inspection, not native runtime verification.
- Direct WLED requires readable device configuration, realtime UDP enabled and a verified0.1–10s device timeout. Devices with inaccessible configuration or unsupported settings are refused until corrected. The check uses WLED0.15.1 configuration fields; `/json/cfg` is not a stable public schema.
- Direct WLED owns the whole controller and blanks unmapped LEDs. The application verifies disabled main-segment-only realtime mode, disabled realtime LED remapping, realtime offset0, DMX address1, disabled sequence filtering, and realtime override0 before streaming. Segment grouping/mirroring/custom hardware mappings are not inferred. UDP has no acknowledgement. Do not interpret HTTP reachability as verified light output.
- HA discovery shows white-only/on-off, unavailable and already-added entities as disabled choices. RGBW/RGBWW service calls set explicit RGBW/RGBWW arrays with white channels zero; no white-channel calibration. HA retains the last color after Stop. Manual changes/automations can compete with synchronization; ownership is advisory, restoration best effort.
- No automatic cross-route identity guess or failover. Re-enter route identifiers when switching; keep one record for each reliably identified physical device.
- Small-image stratified downsampling approximates whole-source averages and can alias very fine patterns. SDR/sRGB assumption only, without HDR/tone mapping.
- Layout limits bound inputs, not a fixed CPU budget. Compact full-weight runs and sparse feather weights keep the tested 2048-zone broad-strip plan below 4 MiB; shared linear-light row sums avoid repeatedly averaging its interior pixels. Recompiling an extreme layout still takes roughly 220 ms in the synthetic probe and runs on the capture worker. Frame delivery may briefly pause during such edits. CPU and memory on other workloads and real capture remain unverified.
- Remote response limits may reject unusually large HA installations: messages32MiB, frames16MiB, deferred events256/8MiB and10,000 discovered/cached lights. WLED JSON is limited to1MiB; oversized replies fail visibly. Parsed JSON can use more memory than its raw byte size. These guards do not establish a universal RSS bound.
- Native UI memory includes GL/windowing driver costs; measured synthetic UI RSS is significantly greater than headless processing. No general low-overhead claim is made.
- No tray/background mode: minimizing keeps syncing; closing stops. No inaccessible process is left running.

Deferred: Hue Entertainment adapter (local bridge, pairing/session ownership inside adapter), other native vendors, HDR, multi-monitor composition, remote frontends, audio reactivity, plugins, Xorg-specific capture. No custom capture backend or GPU processing has been introduced.

- Queued large-response parsing jobs are canceled with their owning session. Tokio cannot interrupt a blocking parser once it starts; a running parse may finish after Stop, with its input constrained by the response limits.
- OS keyring calls cannot be canceled once started. A timed-out save may finish later; one shared gate prevents additional credential calls until it returns.
- WLED restoration cannot provide atomic compare-and-swap against simultaneous manual changes; it preserves the original baseline and skips restoration when an observable change is detected.

The DDP loopback tests now inject ephemeral ports; the revision1 concurrent-test port collision is fixed. No real-world or Windows/macOS testing was performed in revision2.
