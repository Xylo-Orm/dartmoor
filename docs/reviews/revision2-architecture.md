## Findings, ranked

The final implementation at `src/outputs.rs:399` checks Stop and closed owner/frame channels, publishes the actual failure and returns. The new `wled_failed_stop_release_remains_visible` mock first observes successful DDP, removes the HTTP server, signals Stop, joins the adapter and checks the retained failure and absence of retry text. I inspected this correction and independently passed the complete final 49-test suite. Finite leases remain the fallback for the failed explicit release.
2. **Medium — Verification limits remain.** This iteration deliberately did not access real capture, UI, credential prompts or devices and did not build/run Windows or macOS. The older real Hyprland evidence cannot establish runtime behavior for every new change or other desktop environments. Retain these boundaries in the final evidence and score interpretation. No failure of an untested platform is inferred.
3. **Low — Direct saturation/cancellation regressions remain useful.** `src/app.rs:624` correctly retains the latest pending `Apply` until `try_send` succeeds and clears it on session actions; this was inspected but has no direct queue-full regression. `Worker` and `OutputGroup` drop guards are similarly sensible defenses against coordinator cancellation, while the new tests directly cover normal worker Stop and capture errors. A future focused harness can exercise command saturation and forced coordinator cancellation without requiring a real GUI or backend. This is a coverage gap, not an observed failure.
4. **Low — Dense control flow remains.** Parts of `poll_jobs`, WLED steady state and HA steady state are compressed into long expressions even after formatting. Small named helpers would improve reviewability when those paths next change. `OutputAdapter` remains an explicitly documented capability sketch rather than the actual dispatch abstraction; there is no need to create a new framework for this scope.

## Inspected fixes and behavior

- **Capture ownership and cleanup:** `Worker::stop` and `Worker::drop` signal and unpark the capture thread. `CaptureGuard` invokes the trait cleanup on error/unwind and contains a panic from that cleanup call. Engine shutdown bounds both queue submission and coordinator completion; cancellation awaits the coordinator so drop guards run before runtime shutdown. Synchronous backend operations themselves remain non-cancellable, as documented. Normal output cleanup is concurrent and bounded; forced shutdown remains best effort.
- **Frame flow:** session identity rejects prior-session frames, while each accepted frame carries its own immutable sampling configuration. Safe `Apply` commands cannot change routes, source or output cadence. Thus retaining an in-flight frame from the current session is appropriate and avoids starvation during continuous edits. `same_geometry` only resets sampling/smoothing when geometry actually changes. The new gated capture regression proves acceptance of an old-configuration frame after `Apply` and continuity of scalar-edit smoothing.
- **Editor:** discovery additions validate a cloned candidate before committing; imported names are bounded on UTF-8 boundaries. Asynchronous route inspection checks both record identity and the expected route before changing it, so stale replies do not overwrite subsequent edits/removal. Re-selecting desktop capture preserves a saved target. Preview updates compare frame identity rather than counters that restart each session. Pending applies coalesce to the latest editor state when the engine command queue is full.
- **WLED:** controller MAC grouping still gives aliases one output owner. The finite-timeout prerequisite now also requires explicit whole-controller physical indexing settings: no main-segment-only mode, no realtime LED map, zero offset. Following the separate QA review's pinned-firmware findings, the final guard also requires DMX address 1, sequence skipping disabled and readable `lor=0`. I inspected the resulting fail-closed checks and their passing policy regressions; the separate QA report owns the firmware-source derivation. The saved restoration baseline is captured before acquisition and is not replaced by a post-first-frame user change. The new mock regression covers that exact race. The protocol schema remains pinned and fails closed; no physical restoration or timeout claim was verified here.
- **Credentials:** a single process-wide lease covers reads and saves. The blocking closure retains the lease after an async timeout or cancellation until the native call returns. Injected operations test both timeout and cancellation without accessing the OS credential store. A timed-out save may still finish later, and the error explicitly says so.
- **Home Assistant:** refresh reconciles changed/removed capabilities and availability without clearing unchanged-target color caches; event processing follows the same invalidation rule. RGB brightness/chromaticity separation, bounded acknowledgements, post-ack pacing, round-robin selection and stale-frame suppression remain intact. White-only lights are skipped and HA retains its last applied color at Stop.
